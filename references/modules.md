# 八个阅读模块

这份契约规定分析应交付什么；文件格式、命令和入口以本技能的 `SKILL.md` 及脚本接口为准。完整分析运行全部八个模块，各自生成独立目录。用户明确缩小范围时按其范围执行，并在运行记录中列出未运行项。共用一份来源和事实记录，避免八份报告各自重新猜测同一数字；共用事实不能代替各模块的独立分析工作。

推荐学习顺序：06 快速泛读 → 08 论文叙事 → 02 原文对照导读 → 07 方法精读 → 03 批判性阅读 → 05 证据链精读 → 04 文献综述视角 → 01 ARS 科研分析。编号用于固定目录，不强制阅读顺序。各模块以 `content.json` 保存可编辑内容，由脚本生成 `学习报告.html`；Markdown 副本可选。02 逐段导读可另保留专用导读 HTML 和数据。每模块记录实际执行范围，不要只换标题重复摘要。

## 01_ARS科研分析：研究问题与整体论证

**应回答：** 作者为什么提出这个问题，研究设计怎样把问题变成可检验的判断，贡献成立到哪一步，还有什么最有价值的下一步？

完成下列推理：

1. 用具体对象、情境、未知之处和目标结果重述研究问题。区分问题的重要性与作者已证明的结论。
2. 连接“问题 → 关键概念 → 设计选择 → 证据 → 结论”，说明每个连接依赖什么假设。标明贡献是新问题、新方法、新证据、新解释还是新的适用边界。
3. 从研究设计者、反方读者、透明性与伦理三个角度检查论证。每个反方解释须关联原文，说明它影响哪个结论、是否已有证据应对。
4. 把作者承认的局限与读者提出的未检验推断分开；给出能区分主要解释的后续研究建议。
5. 编写能检验理解的问答：研究动机、识别逻辑、一个结论边界和一个后续设计。

**独特产物：** 研究逻辑链、贡献与边界表、反方解释、可检验的后续问题。

**边界：** 本模块借鉴 ARS 的研究审读思路，不等于运行上游整套研究、写作、投稿或伦理审核流水线。不要虚构评委、录用裁决、专家分数、跨模型验证或“已通过伦理审查”。

## 02_原文对照导读：让读者读懂原文

**应回答：** 每一部分在论证中推进了什么？关键段落实际说了什么？哪些限定条件容易被摘要省略？

1. 先确定正文、附录和参考文献的范围，保留 PDF 页码、章节、段落编号。检查分栏、页眉、脚注、断句、数学符号和图表；分段修复完成后再固定编号。修复理由与原始编号映射可追溯。不得用删除难读片段来掩盖提取失败。
2. 阅读所宣称覆盖范围的全部文本，按论证分成若干部分。每部分有完整句形式的主张和推理步骤；步骤说明为什么下一步成立，而不是罗列章节名。
3. 每个正文段落有原文、定位和中文说明。`close` 段提供不直接揭晓答案的阅读提示及独立标示的读后解释；`skim` 段完整转述主要内容、数字和限定；`skip` 段仍标出内容与跳读理由。原文与解释的展开方式以当前 `paragraph_guide` 渲染器为准；不要仅凭折叠效果判断是否完成导读。
4. 优先精读关键定义、设计/识别假设、核心证据、重要公式、范围限制和对异议的回应。新手解释术语，但不把专业读者假定为从未见过研究方法。
5. 保留英文原文并将中文解释与其分区。引用锚点逐字匹配来源；不得为让校验通过而篡改原文。原文提取错字需对照页面说明，不能把错字写成正确概念。
6. 图表紧邻它支持的段落，包含完整坐标、图例、行列及必要表注。关键公式须有可读公式、符号含义、公式用途、假设和原页/裁图；检查正负号、上下标与分母。
7. 每部分通常配 2–3 道回忆题及折叠答案，至少一道“为什么/如何”题；答案引用该部分的段落或图表。任何数字教学例子单独标为例子。
8. 将短结论、段落说明、公式和图表逐一对回来源。用未参与撰写的代理二读；无法分派时执行逐字段自查并如实标明。修订后再确认受影响字段，记录发现、修复与剩余问题。

**独特产物：** 保留原文顺序的可交互导读 HTML，段落数据、论证地图、术语和自测题，分段/裁图修复及二读记录。

**边界：** 总结若只写“本段介绍了方法”不算导读；章节级小结不等于逐段覆盖。没有看到的补充材料和参考文献全文不能算已读。结构校验通过只说明格式约束通过，仍需语义与视觉检查。

## 03_批判性阅读：结论可信到什么程度

**应回答：** 研究中的哪种偏差或不确定性，会怎样改变哪一条结论？

1. 固定评估对象：人群/系统、干预或暴露、比较对象、结果、时间点、独立采样或随机化单位、效应量；先区分描述、预测、关联和因果主张。
2. 先提取估计值、不确定性、分母、纳入排除、失访/缺失、注册计划与补充材料，再评价。明确区分“报告中没写”与“实际没做”。
3. 检查选择、混杂、测量、依赖数据、处理后筛选、多重比较、模型假设和推广范围。区分统计显著、效应大小、实践意义，以及“未拒绝”与“支持无效应”。
4. 每条实质质疑使用“原文位置 → 可观察事实 → 受影响的结论 → 影响路径 → 尚缺信息/可行补救”的格式。也记录设计做得好的地方及其解决的问题。
5. 有需要才选专门框架，并注明版本和评估单位。报告完整性、偏倚风险、跨研究证据确定性不是同一概念；不要把清单勾选数变成质量分。

**独特产物：** 按影响程度排序的质疑清单、条件化结论和设计改进建议。

**边界：** 对单篇非临床论文不硬套整套临床 GRADE 或 RoB。没有正式适用性判断时使用具体方法学分析，不输出认证式标签。

## 04_文献综述视角：这篇论文在讨论中处于哪里

**应回答：** 作者在回应哪一类研究、沿用了什么、改变了什么，还要读什么才能判断其位置？

单篇默认执行“种子论文定位”：

1. 从正文与相关工作提取主题、问题、方法家族和争议，不把引用列表自动当成已经读过的文献。
2. 用主题矩阵比较作者所述的前人观点与本论文主张，明确注明哪些比较仅依据本论文的转述。
3. 区分理论缺口、测量缺口、设计缺口和适用范围缺口；“作者称首次”与“已核验此前无人做过”分开。
4. 给出后续阅读优先级及可直接使用的检索词/检索式，说明每组检索想消除哪项不确定性。
5. 如果本次实际检索，保存来源、日期、完整查询、结果范围和阅读状态。仅纳入确实查看的来源作为独立支持；检索建议与已执行检索分开。

只有用户明确要求系统综述，才扩展为协议、跨来源检索、去重与研究-报告关联、筛选和排除、证据提取/评价、主题综合及引用核验。届时采用适用流程，而不是把单篇定位改个标题。

**独特产物：** 主题/争议地图、种子文献定位表、已读与待读清单、针对缺口的检索计划或真实检索日志。

**边界：** DOI 存在只能支持标识核验，不能证明正文主张；搜索命中数不能充当纳入研究数；未进行系统检索不得声称穷尽领域或已完成系统综述。

## 05_证据链精读：逐条核查主张

**应回答：** 每个主要主张由哪张图、哪张表、哪个实验或推导支持？证据缺口在哪里？

1. 从正文实际措辞列出主要主张，分别标为作者主张、读者推断或教学解释。
2. 建立“主张 → 来源位置 → 直接/间接证据 → 样本/比较/指标 → 假设与限制 → 支持判断 → 待核查”的矩阵。用解释充分的定性判断，不使用不可解释的分数。
3. 逐张核查支撑主要主张的图表：读懂轴、单位、分母、误差线、图例、对照、表注；指出图表支持什么，也指出它无法支持什么。
4. 查方法、数据、基线、消融、失败案例和附录，寻找证据链断点。文字与图表不一致时并列保留并定位，不擅自替作者选择有利版本。
5. 编写导师/组会会问的具体问题，给出当前可回答的部分及仍需查原始材料的部分。提供可移交的结论、用图建议和不可夸大的表述。

**独特产物：** 主张证据矩阵、图表核查、导师问题、待核查清单和组会交接材料。可作为主报告内独立小节/表格；需要单独移交时再输出 JSON、Markdown 或 CSV，不为满足名称机械生成重复文件。

**边界：** 摘要和其他 AI 的总结可帮助定位，不能代替原文证据。原始数据未重跑时写“对照论文核查”，不写“复现成功”。

## 06_快速泛读：建立研究骨架

**应回答：** 研究什么、为什么做、怎么做、发现什么、下一步该读哪里？

先检查标题、摘要、引言、设计/方法总览、核心图表和结论，形成短而具体的导览。对每个答案保留原文位置；结果至少包括关键比较及其范围。用简短术语表补足理解全篇必须知道的概念。

选择最值得精读的原文位置，说明选择理由。完整分析时这只是第一遍，不因为泛读完成就跳过其他模块。若材料仅有摘要，说明范围，不补写详细方法缺点。

**独特产物：** 短版问题—思路—结果导览、精读路线与自测题。无需硬凑神经网络框图或排行榜。

## 07_方法精读：解释它具体怎样做出来

**应回答：** 输入如何变为输出，哪个步骤产生证据，关键假设或实现细节在哪里？

1. 追踪真实研究流程，并把数据/对象在每一步的变化写清楚。实验论文说明招募/采样、随机化、任务、测量、排除、分析；算法论文说明输入、表示、模块、训练、推断、评估。
2. 拆解关键公式：符号/维度、计算顺序、优化或估计对象、假设、与主张的连接；用一个明确标为教学例子的微型计算检验理解。
3. 解释对照、基线、消融或稳健性检查分别排除哪一种解释，哪些仍然无法排除。没有消融的论文说明其实际验证方式，不虚构实验。
4. 记录实际可复用的细节及缺失信息。仅在论文适用时讨论张量形状、损失、优化器、训练轮次；社会实验、理论和质性论文使用各自的设计语言。
5. 把可从论文复述的过程、可按材料实现的过程、已实际运行的过程分开。代码若未查看或运行，不猜具体函数、超参数或成功率。

**独特产物：** 数据/任务流程、公式与符号解释、步骤级方法说明、可复用清单及复现缺口、自测题。

**边界：** “解释为何这样设计”需要连接目标与假设；“方法很先进”不是解释。可行的复现计划不等于完成复现。

## 08_论文叙事：把论文的故事讲明白

**应回答：** 读者进入了怎样的问题场景，遇到什么难点，作者用了什么办法，什么证据让我们改变理解，故事最后能走到哪里？

1. 先给一句话故事：在什么情境，作者想弄清什么，怎样检验，获得什么带条件的认识。再写一段可在约一分钟内读完的通俗版本。
2. 按论文实际论证构造“背景/已有认识 → 未解决的矛盾或疑问 → 作者的关键想法 → 怎样验证 → 证据带来的转折 → 有限结论与尚未解决的问题”。不同论文可合并或调整环节；没有反转就不制造反转。
3. 用明确的主体和动词讲清过程，首次出现的术语就地解释。类比必须标为教学类比并说明对应关系和失效之处；不能增加论文里没有的实验、人物对话或作者心理动机。
4. 关键故事节点都连接到原文页码/章节/图表。可另设“故事节点—原文证据—允许的说法—不能推出的说法”叙事地图，让流畅叙述仍然可查证。
5. 解释作者怎样安排引言、方法、结果和讨论来推进主张，并指出学术论证顺序与实际研究时间顺序可能不同。不要把排版顺序写成真实发现史。
6. 结尾留下读者应能回答的复述题，例如“作者真正操纵了什么？”“哪项证据支撑主要结论？”“为什么故事不能扩展到更大范围？”给出折叠答案。

**独特产物：** 独立目录中的通俗故事阅读版，内含叙事地图、原文证据锚点及自测题。叙事地图可直接由 `content.json` 的表格呈现，无需另造文件。它应比逐段导读短且连续，读完能复述问题与论证，而非只记住夸张标题。

**边界：** 简化术语不简化因果、分母、适用条件和不确定性。候选叙事 skill 的高星只作为发现线索；只吸收同一论文试读中确实改善理解且没有牺牲忠实度的做法。
